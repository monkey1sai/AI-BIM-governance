# CFD 第一版周邊量體與第二版室內通風決策

日期：2026-10-02。狀態：**owner 決策已確認；以下新增能力尚未實作、求解或真站驗收**。

本檔承接 [呈現對齊契約](cfd-presentation-parity-contract.md) 的 D1／D2。Owner 在「CFD 進度與決策」選定 D1=A、D2 留第二版，並於本輪明確採納該對話的專家建議作為決策。下列要求是需求與驗收依據；訪談中的假設、案例數字與文獻引述不作本 repo 的完成或精度證據。實際 payload 仍以 `tests/contracts/*.schema.json`、coordinator OpenAPI 與 source/tests 為準。

## 1. 決策與版本邊界

| 決策 | 已確認範圍 | 交付定位 |
|---|---|---|
| D1=A，第一版 CP9 | 每 run 最多 50 個手動周邊量體方塊，具有尺寸、位置、高程、旋轉及來源；實際加入計算與畫面 | 明確風況與周邊條件下的室外風速、流向、外牆壓力比較，維持 `design_comparison_only`／`screening` |
| D2，第二版 CP10 | 室內開窗通風整體延後；採手選 `IfcWindow`／`IfcDoor` 清單（B）的方向，先做幾何與連通性盤點 | 使用者在 BIM 點選並確認名稱、樓層與位置，系統保存 GUID；不是要求使用者抄 GUID |
| 第一版品質與比較 | 同條件情境比較、固定量測區、壓力基準、共用色階、幾何與數值可信度報告 | 以可追溯數值支援初步設計比較；流線數量、動畫或軟體測試不作物理精度證據 |

第二份 IFC／A3 federation 與 GIS 不屬於 D1 首版。本輪不預留未使用的 mesh 匯入 API。第一版不做室內流量／ACH、熱浮力、結構風荷載或法規符合判定。這是產品分版決策，並未授權新增求解或延長先前探針。

| 地表粗糙度與湍流 | 沿用具來源的既有設定，揭露 `z0`、湍流模型與入流假設 | 配對比較保存相同設定；不得為畫面效果改物理條件 |
| 周邊範圍、計算域與網格 | 依共同幾何重新檢查最高量體、上／下游／側面／頂部距離、各風向 blockage 及局部細化 | 幾何與域 bbox、實際高度基準、格數／耗時估算及限制；展示 ROI 與求解域分開記錄 |

≤50 是產品輸入上限，不代表周邊涵蓋充分或計算便宜。鄰棟／主棟高度比及棟距／高度比可作情境描述，不能作通用好壞門檻。估計資料允許使用，但結果持續保留估計標示；尚未取得現場尺寸，不得用任意測試方塊冒充真實鄰棟。

## 4. 幾何、情境與結果一致性

- 保存主模型版本、conversion ID、主 USDC hash、周邊資料版本／canonical hash、實際計算幾何 hash 與 run ID。Canonical 化、排序及 hash 欄位的確切格式由 CP9a 在 machine contract 中定義並測試；本檔不新增可接受的 request 欄位。
- 主棟與周邊量體分開識別；`ContextMassing` 顯示相同尺寸、位置與旋轉的已提交量體。提交前的預覽須與目前結果分清楚，不能把新增量體放到舊風場上宣稱完成。
- 編輯尺寸、位置或來源後建立新情境版本；結果持續綁定原版本。新增周邊須有新計算結果，不能沿用「無鄰棟」的 U／p。
- 合併幾何改變估算、域或格數時，先揭露差異與限制；超出既有 cap 要停在估算，不得靜默刪鄰棟、封通道或降低網格以通過。
- 比較時驗證主模型、風況與量測定義相容；舊 run 無周邊 metadata 時，仍可顯示，但不能假定它是已證明可比較的「無周邊」基準。

## 5. 第一版結果與配對比較

先支持少量固定點／區域，例如入口、廣場與棟間通道。保存模型座標、取樣高度、區域邊界、面積權重、有效取樣範圍與缺值規則。同一組比較使用相同定義；資料不足須如實顯示，不跨建物實體插值成有效空氣樣本。

| 結果 | 必須明確的定義與限制 |
|---|---|
| 行人區域風速 | 區域的風速大小：面積加權平均、面積加權空間 P95、最大值與位置；空間 P95 不是全年時間超標率 |
| 流向與低速／回流 | 由有來源的向量與切面輔助判讀，不能靠流線密度判定強弱；局部垂直分量不能為了「水平」畫面而抹除 |
| 表面壓力 | 保存原運動學壓力 `p/ρ`、基準值／位置及單位 `m²/s²`；未指定且驗證密度時不轉 Pa |
| 壓力係數 Cp | 無因次；`Cp = (p_physical - p_reference)/(0.5 × rho × U_ref²)`。相同定密度、同壓力基準時，等價 `2 × (p_kinematic - p_reference_kinematic)/U_ref²`；`U_ref > 0`，參考值／來源、`U_ref`／`z_ref` 必須存在 |
| 有／無周邊配對 | 同主模型、風向／北向、`U_ref`／`z_ref`、粗糙度、湍流／求解方法與量測區；網格策略、解析度及各自差異必須揭露。無周邊案例標為診斷基準，不冒充現況 |
| 變化量 | 同一指標給絕對差與適用的相對差；基準近零時不給誤導百分比。CP9c 在契約定義近零判定與缺值規則；不可拿目前畫面顏色推算數值 |
| 共用色階 | 配對結果採相同 quantity、單位及範圍；保存真實極值並標示飽和。不可讓兩個自動色階相同顏色假裝同值；Cp／p／速度不能混用圖例 |

表面比較必須有可重現的區域或對應方法；拓撲改變時不能直接逐頂點相減。首版不必先做複雜雙視窗 UI，但數值配對、條件與差異表必須可核對。採已達收斂條件的穩態平均場作主要比較依據；未收斂時如實標示，不能給確定改善結論。既有非穩態同步播放保留為補充，不把 19 個短時快照宣稱為長期統計、極值風壓或經驗證工程精度。

## 6. 可信度與新增計算的停止條件

第一版每份結果保留幾何版本與近似、風況、網格、求解狀態、量測定義及未驗證項目。證據分三類：

1. **軟體與呈現**：schema／source binding／幾何與 hash 一致、測試、Kit ACK、Chrome 畫面；證明資料與操作正確。
2. **數值檢查**：收斂、質量平衡、代表性粗／細網格、周邊涵蓋及域範圍敏感性；時間解析度在非穩態案例另查。兩層粗細差先作敏感性，不宣稱完整 GCI、網格獨立或物理 validation。
3. **實驗或現場驗證**：與風洞／量測比較；尚無新情境證據就列缺口，不由測試綠燈升級 `validation_level`。

各數值門檻、量測方法及比較指標在 CP9d 的實驗計畫先定義。若情境差異小於或接近網格／範圍造成的變化，須標「改善幅度尚不確定」。納入更多一圈周邊的敏感性仍須有依據與成本核對；少於 50 個不代表涵蓋足夠。

任何新的 181 網格／求解執行前，先提供可審查計畫：具體情境與輸入 hash、風向／run 數、格數與估計記憶體／耗時、CPU／磁碟限制、全部階段的時間硬上限、是否延長或重試、結果保留與程序清理方式、停止條件。取得 owner 對該計畫的預算授權後才執行。估算超限、來源／幾何不符、未知在跑工作、時間到限或需超出授權時停止並保留記錄；不改 cap、不中斷其他工作、不自動重跑。先前單次非穩態探針及其剩餘時間不適用此輪。

## 7. D2 第二版的承接要求

- 先在 BIM 點選少量窗／門，保存 GUID 與名稱、樓層、位置，再核對實際開口幾何、法向、有效面積、開啟程度、窗型／阻力。GUID 只識別構件，隱藏窗 mesh 不代表流體域已打通。
- 盤點室內房間、隔間、門與開口的連續流體域及網格可解析性；沿用原 BIM 細節，不把戶外粗化外殼當室內模型。
- 首版 V2 方向為有限開口的風驅、等溫案例；熱浮力／溫差另定範圍。先估格數、耗時與可執行性，再安排求解預算。
- 觀察開口兩側壓差、實際通風流量；房間容積與流量定義完整且已求解後才算 ACH。第一版牆面壓力不能直接變成室內通風量。
- 室內外耦合或有依據的分開求解方式留 CP10 設計檢查。使用 V1 閉牆壓力作邊界前，要檢查開窗後的適用性；不假定開口不影響外部流場。

以上是已採納的 V2 需求方向，並未核定室內 profile、API、格距、總格數、計算時間或耦合方法；不在 V1 建立室內求解流程。

## 9. 技術定義參考

- [OpenFOAM 運動學壓力](https://doc.openfoam.com/2312/tools/processing/solvers/algorithm-kinematic-pressure/)：`p = p_physical/ρ` 的單位語意；本 repo 實際出口基準仍以 case writer 與 metadata 核對。
- [NASA NPARC 網格收斂指引](https://www.grc.nasa.gov/www/wind/valid/tutorial/spatconv.html)：用網格序列檢查離散誤差，辨識敏感性、收斂與不確定性。
- [NASA NPARC Validation Assessment](https://www.grc.nasa.gov/www/wind/valid/tutorial/valassess.html)：計算檢查與實驗／真實觀察比較的證據分工。

參考文件支持上述定義與證據分工，不代表此 repo 的新情境已驗證；HTTP 存取或摘要索引亦不作 runtime／精度證據。

## 估算與實際（`b75af0`）

這是同模型、同案例的樣本內比較，不能拿來證明估算器對新模型或新網格的準度：

- 本模型 2026-09-22 跑過的 N 0° 是 3,048,141 格、483 步、1,715 秒，`cfd_options.json` 的預設依據引用的也是這個案例。`b75af0` 是 3,048,155 格、483 步，等於重跑同一個案例。
- 估算的加細比例與每格耗時，都取自本模型這類逐風向樣本的中位數。

| 項目 | 估算 | 實際 | 差距 |
|---|---|---|---|
| 格數 | 3,061,069 | 3,048,155 | 估算多 0.42% |
| 總耗時 | 1,914.8 秒（前處理保留 300 秒＋求解 1,614.8 秒） | 1,747 秒（10:18:23Z–10:47:30Z） | 估算多 9.6% |

- 前處理的 300 秒是設定檔的保留值，沒有實測。coordinator 也不提供各階段的時間，所以實際值無法拆成前處理與求解。
- 舊案例的求解是 1,715 秒，估算的求解只有 1,614.8 秒，可能偏低（推論）。
- 迭代數不影響這次的估算：endTime 600 高於歷史典型值，時間比例取 1。

## 發現

- **全域 CSS 蓋過 legend 樣式：** 全域 reboot CSS 的 `legend { float: left; width: 100%; font-size: calc(1.275rem + .3vw) }` 會穿過 `.uc-root` 防火牆，因為 `:where()` 的優先度是 0。結果有兩個：
  - 「一般」分區標題被放大到 24px。
  - 風向 fieldset 的 legend 被當成 4 欄 grid 的一格，寬度只有 48.75px，文字被擠成直排。

  本收尾 PR 在兩個 legend 上明確取消 float 並改為繼承字級。
- **瀏覽器視窗被判定為隱藏：** owner 的 Chrome 視窗被其他視窗蓋住，瀏覽器回報 `document.hidden` 為 true。
  - 面板照設計在隱藏時暫停輪詢，所以 `b75af0` 的結果列沒有在面板上刷新，改以 API 確認。
  - Chrome MCP 截圖偶爾因此逾時。
- **不是本次驗證送出的 run：** `c57d8f`（07:49Z）、`b78b07`（09:52Z）、`669057`（10:47Z）也是同一個模型的單向 run，設定都是背景格 6 m、沒有 endTime、由 API 送出。它們會佔用單一求解 worker 的時間。

Why this is bootstrap debt: this PR turns the report-only Agent Governance Policy module (#565)
into an adjudicator. It adds `verify-governance-policy.ps1` and the module behaviour suite to the
required agent-governance CI job, deletes the 182 superseded text assertions from
`test-agent-governance-check.ps1`, and registers the module, gate, and behaviour suite in
`Get-SelfReferentialMechanismPaths` (§2.1 upgrade rule, same PR). The branch adjudicates itself
with the changed adjudication surface, so only a post-merge run from main can prove the wired
mechanism against itself.

## What was deleted, and what holds each invariant now

- 182 of the 195 lines mapped by the rules' `replaces` provenance were deleted. Every deleted
  assertion's invariant is held structurally by scripts/agent-governance-rules.json through
  scripts/lib/agent-governance-policy.psm1 (37 rules, all green below).
- 13 mapped lines were RETAINED because block-by-block re-anchoring showed the provenance was
  overbroad — the structural rules do not subsume them:
    L259-262  agent-task template body markers (acceptance_criteria / validation_commands /
              evidence_contract / docs/plans)
    L267-274  per-suite presence greps for eight OTHER suites in agent-governance.yml
    L291      ci.yml expected-job foreach
  The four affected rules' `replaces` fields were corrected to say "additive" instead of
  claiming those lines.
- The deleted L466-473 post-mortem block (pwsh run-count arithmetic) is held by the
  `agent-governance-steps-use-pwsh` rule (yaml_every over jobs.suite.steps). The old block's
  "exactly one bash shell" count covered jobs.scope, which the rule deliberately does not: the
  count was the arithmetic-coincidence antipattern this migration removes, and the suite-scoped
  universal rule is the stated invariant.

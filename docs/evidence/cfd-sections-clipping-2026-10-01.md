# CP8 剖面保留半空間補修（2026-10-01）

## 問題與實際重現

PR #1010 部署後，原 session 與 CFD source 核對相符。實際七剖面結果的 Z 0.25H 操作完成原狀態讀取、圖層、裁切、正視角、正交投影五項 Kit 確認，但風速色面消失，只剩部分向量；因此指令 ACK 不足以判定畫面通過。

在可見 headed Chrome 的同一 session、同一結果、同一相機，只將 Z 裁切的方向從 `+1` 改成 `-1`，立即恢復風速色面。沒有重算或改寫原 artifact。色面 Z=5.769999980926514 m，裁切位置 Z=5.8199999809265135 m；Kit 回覆的平面係數從 `[0,0,1,-5.8199999809265135]` 改成 `[0,0,-1,5.8199999809265135]`。

RTX 保留 `n·p+d >= 0` 的半空間。原本正向係數保留取樣面上方，反而刪除取樣面。X right、Y back、Z top 三個既有正視角均從正軸看向負軸，應保留裁切後方的取樣色面。

## 修正範圍

只修正 viewer 的 CP8 自動剖面序列：使用反向法線，保持向相機偏移 0.05 m，並以實際送出的方向核對 Kit effective 讀回。手動裁切、相機與退出復原、authority、API、資料結構、環境變數及部署流程均無變更。既有 immutable CFD artifact 不變。

新增三軸回歸檢查，確認取樣面及後方點位被保留、相機側點位被排除，以及退出仍還原原相機與圖層。修正前 3 項失敗、原有 7 項通過；新增測試的首次語法解析失敗已修正後才建立此基準。

## 驗證狀態

- viewer 2,923 項／194 檔通過，typecheck、session-first、struct-log 23 項、production build 均 exit 0。
- root contracts 1,416 項通過，diff whitespace 檢查通過。
- Chrome 的 X 垂直剖面也在反向後呈現色面；退出三步 Kit 確認，原透視 FOV 35.92104613528987°、相機位置與圖層可見性恢復，位置最大偏差約 3e-14 m。
- 已確認的 Chrome 手動方向對照是原因診斷，不能替代本補修合併部署後的自動序列驗收；後者尚未驗證。
- coordinator、streaming 與 CFD tools 原始碼未變，本機未重跑這三個服務全套；由 CI changed-path classifier 決定工作範圍。

## 仍存在的限制

- 本次真模型 layer 28,186,047 bytes，仍超過 CP1 約 25 MB 目標；暖載入單次 372 ms，未測冷載入或 13 面真模型最大值。
- 裁切是全場景 RTX 設定，向量幾何貼近裁切邊界，可能部分被切除；不能只憑可見性讀回宣稱所有箭頭均完整可見。
- 結果是 screening 穩態外部風場，建物內部為實體，沒有室內計算或工程精度證明。
- 真北資料未知，維持相對專案北。真正非穩態 U/p 播放整合仍是另一個未完成範圍，不能以本剖面成果代替。

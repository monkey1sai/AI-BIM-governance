# CFD 設定可調 B 階段 §7 本機驗證（2026-09-24）

依 `docs/plans/building-energy-cfd-b-engine-params.md` 第 7 節，在開發機的本機 docker 跑 AIJ Case C 與實案。

- 引擎版本：main `6a18fbd`（B1a，#942），在固定於這個 commit 的獨立 worktree 執行。
- 求解環境：OpenFOAM v2412（`opencfd/openfoam-default:2412`）、8 進程，不設 docker CPU 上限，與 E4、S5b-2 相同。
- 每個變體各跑一次；endTime 600，未收斂時自動延長一次到 1,200 步。
- 沒有動 181、沒有部署，也沒有改 service。

## 結論

- **AIJ：** V1、V2 都通過 owner 訂的五項門檻。格數約為 E4 的 36%，耗時約 40%，準確度與 E4 相當。
- **實案：** 放粗 1 層、2 層都通過準確度門檻（峰值差 −1.2%、−1.1%，面積平均差 +0.06%、+0.18%）。
  - 但格數只降到 55.7%、50.6%，耗時只降到 55.8%、53.6%，都沒有達到「至少減半」。
  - 原因是這棟建物的等向加細盒很大，放粗只能減少盒外的背景格，詳見下方「實案為什麼省不到一半」。

- **收斂：** 三者都在 600 步未收斂、觸發延長，並在延長段收斂（663、642、670 步）。
- **網格品質：** 三者的 checkMesh 都回報 `Failed 1 mesh checks`，原因是少數高偏斜面：基準 4 個、最大偏斜度 8.08；放粗兩個變體各 3 個、最大 5.22。S5b-2 的 3 m 層同樣有 4 個、最大 8.36，所以這是外殼表面加細本來就有的現象，不是放粗造成的。最大非正交角三者都是 64.56°。
- **行人面：** 三者的取樣面積都是 96,075 m²，取樣範圍相同。

### 實案為什麼省不到一半

- 這棟建物的等向加細盒體積約 875 萬 m³，上游端超出 5H 的入口約 51 m。盒內的 1.5 m 格子本來就是格數的大宗，放粗只能減少盒外的背景格。
- 以放粗 1 層為例：背景格從 3,263,586 降到 418,584，但總格數只從 5,392,753 降到 3,006,356。
- AIJ 的方塊群用 bbox 盒，盒子小，放粗後省得到 6 成以上。
- 所以放粗能省多少，取決於加細盒占計算域的比例。

### 基準為什麼比 S5b-2 多 21% 格

- 外殼逐位元組相同，blockMesh 也相同（背景格 3,263,586），差別只在等向加細盒。
- `29e4eb9`（S5b-2 自審）把等向盒改成「外殼頂點重心為圓心、最遠頂點距離為半徑」，對每個風向都相同；S5b-2 的網格是在這之前跑的。
- 以現行定義，這棟建物的盒子離 bbox 上游約 7.2H、下游約 4.6H；S5b-2 當時約 2.6H、3.6H。
- 所以實案一律和今天重跑的基準比，S5b-2 的數字只供參考。

## 比較條件與限制

- **每項只跑一次。** 各變體是否收斂已在上表註明。
- **hit rate 的鑑別力有限。** 36% 的門檻只比 E4 的 40% 低約一個標準誤。
- **S5b-2 的面積平均風速本身沒有網格收斂**（只有峰值收斂），所以 5% 門檻的鑑別力有限。
- **耗時是在共用主機上量的，只能當近似值：**
  - E4 當時沒有記錄主機負載。
  - AIJ 兩個變體只記錄了起跑和結束的瞬間 CPU：V1 為 65% 與 18%，V2 為 13% 與 95%。
  - 實案從 09:07 UTC 起每 30 秒取樣一次主機 CPU，平均值：基準 68.3%（只涵蓋後半段）、放粗 1 層 70.5%、放粗 2 層 70.5%。8 個 OpenFOAM 進程本身約占 20 個邏輯核心的 40%。
  - 另一個 session 在 09:05～09:22 UTC 部署 181 並在本機跑 Chrome E2E，只和實案基準（08:33～09:43 UTC）重疊，放粗兩個變體沒有碰到。
  - 實案的耗時比例與格數比例幾乎一樣（55.8% 對 55.7%），表示耗時跟著格數走。格數比例不受主機負載影響，單看格數也沒有減半。

## 重現

- **AIJ：** 在 `tools/cfd` 執行

  ```bash
  python -m bimcfd aij-case-c --data-dir <AIJ Case C 資料夾> --out <輸出> --run-id <id> --center 1D --wind-direction 0 --cell 1.5 --refinement-box bbox --np 8 --outer-coarsening-levels 1
  ```

  V2 另加 `--ground-band-height-h 0.2`。

- **實案：** `CaseParams(wind_from_degrees=0, true_north_degrees=0, background_cell_m=3.0, n_procs=8, refinement_box_mode="isotropic")`，放粗變體另加 `outer_coarsening_levels=1` 或 `2`。
  - 每個變體走 CFD Case Run 的 `solve_case`、`record_case`，行人面指標用 `convergence.plane_metrics`（裁到 `plane_clip_box`）。這和 `bimcfd converge` 每一層做的事相同，只是單一格大小。
  - 外殼與前處理輸入是私有資料，不在 repo 內。

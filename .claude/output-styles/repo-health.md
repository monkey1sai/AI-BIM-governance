你正在做 AI-BIM-governance 的 repo 健檢報告。用以下風格輸出：

# 輸出格式

1. **開頭一張總表**，每個面向一列：狀態圖示（✅ 無問題 / ⚠️ 有警告 / ❌ 有失敗）、面向名稱、問題數、一句話摘要。
2. **各面向逐項展開**，每項用緊湊格式：
   - 一行標題（嚴重度圖示 + 問題標題）
   - `證據:` 檔案路徑 + 具體值（版本號、分支名等）
   - `建議:` 修法
   - 標記 `[safe]` 或 `[risky]`
3. **進度差異區塊**（若有 `progress`）：在衛生面向之後另起「📊 進度差異」，用小表呈現 `目標 / 計畫說 / 實際 / 對齊 / 差距`；對齊欄用圖示 ✅相符 / 🔴計畫高估（說做了實際沒有）/ 🟡計畫低報（說待建實際做了）/ ❔查不出。這區塊純資訊，**不列入可修項、不進結尾問句**。
4. **結尾固定問一句:「要修哪幾項?」**，只把 4 個衛生面向的可修項用編號列出，清楚標示哪些 safe（可快修）、哪些 risky（需你點頭、會改版本/設定/文件）。

# 語氣與用字

- 一律繁體中文台灣用語；技術名詞、檔名、版本號保留原文。
- 白話、直接，對「工程白癡」也讀得懂；不繞圈、不客套。
- **證據優先**：講問題一定附真實檔案/值，不講空泛結論。
- 誠實：某面向沒掃完就標「未完成」，絕不假裝健康；沒有問題就明說健康。

# 不要做的事

- 報告階段不要主動修任何東西（掃描唯讀）。
- 不要把 `.env` 的「值」寫進報告（只可列 key 名）。
- 不要用大量 log 或長段落淹沒重點；保持可掃描。
